# CLAUDE.md

Guidance for Claude (or any agent) working in this repository.

## Project

Voice of Customer analyzes Steam game reviews against a game's marketing
claims to surface hidden strengths, marketing disconnects, and vocabulary
gaps between how players talk about a game and how it's marketed.

## Repository layout

```
scripts/    Pipeline scripts (see below) and scripts/validate_project.py
data/       JSON produced/consumed by the pipeline
output/     Generated artifacts (dashboard.html)
CLAUDE.md   This file
README.md   Human-facing project overview
```

## Pipeline

Each stage reads the previous stage's output and writes one JSON file to
`data/`, except the last stage which renders the dashboard to `output/`.

| Script | Output |
|---|---|
| `scripts/collect_reviews.py` | `data/reviews.json` |
| `scripts/collect_marketing.py` | `data/marketing.json` |
| `scripts/find_themes.py` | `data/review_themes.json` |
| `scripts/find_gaps.py` | `data/gaps.json` |
| `scripts/vocab_gap.py` | `data/vocabulary.json` |
| `scripts/build_dashboard.py` | `output/dashboard.html` |
| `scripts/prepare_marketing_insights.py` | `data/marketing_insights.json` |
| `scripts/build_marketing_dashboard.py` | `output/marketing_dashboard.html` |

`app.py` (WS8) is a Flask wrapper that runs this pipeline on demand from a
browser form, reusing any valid existing data/output files instead of
regenerating them. See "Running the marketer-facing app" below.

Run `python scripts/validate_project.py` at any time to check which
pipeline scripts and data files exist, and whether existing JSON files
have the required fields below.

## Required data formats

### `data/reviews.json`

Top level:
- `game_name`
- `source_url`
- `app_id`
- `review_count`
- `reviews` — list of review objects

Each review object:
- `review_id`
- `text`
- `recommended`
- `date`

### `data/marketing.json`

Top level:
- `game_name`
- `source_url`
- `claims` — list of claim objects

Each claim object:
- `claim_id`
- `text`

### `data/review_themes.json`

Top level:
- `game_name`
- `themes` — list of theme objects

Each theme object:
- `theme_id`
- `theme`
- `sentiment`
- `mention_count`
- `keywords`
- `example_review_ids`
- `quotes`

### `data/gaps.json`

Top level:
- `hidden_strengths`
- `marketing_disconnects`

### `data/vocabulary.json`

Top level:
- `review_only_terms`
- `marketing_only_terms`
- `same_idea_different_words`

### `data/marketing_insights.json`

Top level:
- `game_name`
- `source_url`
- `app_id`
- `model`
- `perceptions` — list of perception objects
- `top_recommendations` — list of recommendation objects

Each perception object:
- `perception_id`
- `theme_id` (traces back to `review_themes.json`)
- `customer_perception` (human-readable, never a raw theme label)
- `current_marketing_position`
- `alignment` — `ALIGNED` | `UNDERREPRESENTED` | `OVEREMPHASIZED`
- `recommended_action`
- `suggested_messaging`
- `evidence_quote` (verbatim, traces back to a `review_themes.json` quote)
- `evidence_review_id` (traces back to `reviews.json`)

Each recommendation object:
- `recommendation_id`
- `action` — `ADD` | `KEEP` | `REDUCE` | `REFRAME`
- `title`
- `detail`

Generated by `scripts/prepare_marketing_insights.py` using the Anthropic
SDK (`ANTHROPIC_API_KEY`, default model `claude-sonnet-5`). Never invents
evidence — every `theme_id` / `evidence_review_id` / `evidence_quote` is
checked against the real source files before the file is written.

## Running the marketer-facing app (WS8)

```
pip install -r requirements-ws8.txt
export ANTHROPIC_API_KEY=...   # required to generate marketing_insights.json
python app.py
```

Open `http://127.0.0.1:5000`, enter a game name (Source URL is optional —
left blank, it's resolved via Steam search), and click "Analyze Brand
Perception". The right-hand panel shows live progress; each pipeline stage
reuses its existing `data/`/`output/` file when it's still valid for the
resolved game instead of regenerating it. When done, click "View Brand
Perception Dashboard" to open `output/marketing_dashboard.html`.

## Conventions

- Every script in `scripts/` reads its inputs from `data/` (or hits an
  external source for the two collection scripts) and writes exactly one
  file, per the pipeline table above.
- IDs (`review_id`, `claim_id`, `theme_id`) are stable strings referenced
  across files — e.g. `example_review_ids` in `review_themes.json` refers
  back to `review_id` values in `reviews.json`.
- Keep `scripts/validate_project.py` in sync if the expected file list or
  required fields change.
